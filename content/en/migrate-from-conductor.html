Migrate from Conductor

Open your Conductor worktrees in Orca, move your setup scripts, and resume your agent sessions — including Conductor Cloud work before Cloud shuts down.

Conductor and Orca share the same model: every task gets its own git worktree on its own branch, with an agent working inside it. Conductor workspaces are ordinary git worktrees, so Orca opens them in place. Nothing is copied or moved, and uncommitted changes stay where they are.

Timeline: Conductor Cloud shuts down on November 20, 2026, and the Conductor desktop app is supported until early 2027.

Used Conductor Cloud?

Cloud workspaces aren't on your Mac, so Orca can't see them yet. Before the steps below, save that work with Move your Conductor Cloud work at the end of this page. Conductor Cloud becomes read-only on November 13, 2026 and starts deleting cloud data on November 20, 2026.

1. Add your repos

Install Orca, then click Add project at the top of the sidebar and pick the same checkout Conductor used — not a fresh clone. Conductor's workspaces are worktrees of that checkout, and Orca finds them through it.

Not sure which checkout that is? Run this inside any Conductor workspace:

git rev-parse --path-format=absolute --git-common-dir

It prints a path ending in .git. The folder containing it is the checkout to add.

2. Show your Conductor worktrees

Orca hides worktrees it didn't create until you choose to show them.

  1. Open the project's actions menu in the sidebar and choose Show hidden worktrees (it reads Hide non-Orca worktrees when they're shown by default).
  2. In Non-Orca worktrees, click Show next to each Conductor workspace still listed as hidden. They usually live under ~/conductor/workspaces/, or in a .conductor/ folder inside the repo on older Conductor versions.

Each one keeps its path, branch, and uncommitted changes. Orca doesn't run setup on them — they're already set up.

If a workspace is missing from the list, run git worktree list in the checkout from step 1 to confirm it belongs to that repo.

Don't archive these in Conductor

Archiving a workspace in Conductor deletes its folder, which is now also your Orca worktree. Quit Conductor instead.

3. Move your scripts

Let an agent do it

Open a worktree in the repo and ask your agent:

Convert this repo's Conductor config (conductor.json or .conductor/settings.toml) into orca.yaml,
following https://orca.dev/docs/migrate-from-conductor. Map CONDUCTOR_* variables to ORCA_*,
drop CONDUCTOR_PORT, and list the run actions so I can save them as Quick Commands.

To do it by hand, pick one of the two options below for setup and archive scripts (if you do both, see the note after them), then save your run actions as Quick Commands.

Option A: save the detected command (just you)

When a project has a conductor.json and no Orca setup yet, the sidebar shows an Add a setup script card: Found a setup command in conductor.json. Click Save local setup. Orca saves the setup and archive scripts as local commands in Settings → Repository, then runs setup in every new worktree in that project and archive before deleting one. The run script is skipped — save it as a Quick Command — and .conductor/settings.toml isn't read, so copy its commands by hand.

Option B: commit orca.yaml (your whole team)

Put the scripts in orca.yaml at the repo root:

scripts:
  setup: |
    bun install
    cp "$ORCA_ROOT_PATH/.env" .env
  archive: |
    docker compose down
  • setup runs in each new worktree right after Orca creates it.
  • archive runs before Orca deletes a worktree.

Merge orca.yaml to your default branch and pull it into the checkout from step 1. New worktrees read setup from the branch they start from, and deletes read archive from that checkout. See Worktrees for the full lifecycle.

Did both?

If you saved the card before adding orca.yaml, the project's Command source & orca.yaml setting (Settings → Repository) is Local only, which ignores orca.yaml scripts. Set it to orca.yaml only. Avoid Run both here — it runs the local commands and the orca.yaml scripts back to back, so the same migrated commands would run twice.

Run button and actions: Quick Commands

Conductor's Run button and named actions become Quick Commands. Save each one once — a label and the command, such as bun dev or bun test — with Add Command in Settings → Quick Commands, or + Command in the Quick Commands menu on a worktree's tab bar. Choose Project scope to show it only in this repo's worktrees, or Global for every repo.

Run one from the Quick Commands button in any worktree's tab bar: Orca opens a fresh terminal tab in that worktree and runs it. Right-click a terminal to insert a command into it instead. The same list is on Orca mobile, and it works in worktrees on a Remote Orca Server.

Variables and ports

Scripts that read CONDUCTOR_ROOT_PATH keep working — Orca sets it to the same path as ORCA_ROOT_PATH. Replace CONDUCTOR_WORKSPACE_PATH with ORCA_WORKTREE_PATH (or just use the current directory) and CONDUCTOR_WORKSPACE_NAME with ORCA_WORKSPACE_NAME.

Orca doesn't reserve ports per worktree, so drop --port $CONDUCTOR_PORT. Most dev servers pick a free port on their own.

Copying .env in setup works, but you can list gitignored files in .worktreeinclude instead and Orca copies them into every new worktree. See Shared directories & gitignored files.

4. Pick up your agents

Claude Code, Codex, Cursor CLI, and the other supported agents use the subscriptions and keys you already have.

Turn on Chat UI for the Conductor chat look

Orca opens agents in their own terminal CLI by default. For a chat view like Conductor's, with rich messages, visuals, and images, open Settings → Agents and under Open agents as choose Chat. New sessions for supported agents, including Claude Code and Codex, then open as chats. If some agents stay in the terminal because you chose CLI for them before, click Set all to Chat in the confirmation. You can still pick Chat or CLI for each agent in that page's Installed list. See Chat UI.

Resume a Conductor conversation

To pick up a Conductor conversation, select the worktree, open the right sidebar's Agents tab (Agent Session History), find the session, and click Resume. Orca lists every transcript the agent CLI saved in its usual place, like ~/.claude for Claude Code. To continue a Claude Code or Codex conversation as a chat, choose Resume in New Chat from the session's menu instead. Because the worktree keeps its path, claude --resume in its terminal works too. Claude Code removes sessions older than 30 days by default, so older chats may be gone.

To keep a copy of every Conductor chat, use Conductor's Settings → Account → Export data. Orca can't import that export.

5. Retire Conductor

  1. Quit Conductor and move it to the Trash.
  2. Keep ~/conductor/workspaces/ (or the repo's .conductor/ folder) while any of your worktrees still live there — deleting it deletes your work.
  3. When you finish with an old worktree, delete it from Orca. Orca runs your archive script, removes the folder, and deletes the branch if it's fully merged (unmerged branches are kept — see Preserved branches).
  4. After the last old worktree is gone, run git worktree prune in each repo. Then you can delete ~/conductor/workspaces/ and any .conductor/ folders.
Check before deleting ~/conductor/

If a project you added in Orca lives under ~/conductor/ (common after Transfer to local), that folder is the repository every one of its worktrees depends on. Keep it, or move your work to another clone first.

Move your Conductor Cloud work

On November 13, 2026, Conductor Cloud becomes read-only: you can read chats and export data, but agents stop taking messages. On November 20, 2026, it shuts down and Conductor starts deleting cloud data.

Orca doesn't host machines. Cloud work moves to your Mac, or to an always-on machine you control.

Save your work

Do this before November 13 if you can.

  1. Push every branch. Commit everything, including new files (git add -A), and push. Gitignored files like .env aren't pushed — copy them somewhere safe.
  2. Export your chats. In Conductor, open Settings → Account → Export data. It's your only copy of cloud chats.

Continue on your Mac

  1. In Conductor, right-click the cloud workspace and choose Transfer to local. This moves the workspace and its chats to your Mac.
  2. Follow steps 1–4 above.

A transferred workspace can be attached to Conductor's own copy of the repo under ~/conductor/ instead of your clone. Run git rev-parse --path-format=absolute --git-common-dir inside it. If the path is under ~/conductor/, add that folder as the project. Or, since the branch is pushed, create a new worktree in your usual clone and choose that remote branch under Branch from in the New Workspace composer.

Keep agents running with your laptop closed

Cloud workspaces kept working while you were away. In Orca, run agents on a machine you own — see Ways to run Orca:

  • Remote Orca Server — keep Orca running on a Mac mini, home server, or cloud VM, and connect from your laptop or phone. Agents keep going when your laptop sleeps.
  • SSH — run worktrees on any SSH host while the UI stays on your laptop.
  • Cloud VMs — give each worktree its own sandbox or VM from a provider you already use, like Fly, Modal, or Vercel Sandbox.

Install and sign in to git and your agent CLIs on that machine; your laptop's logins don't carry over. Then create a worktree from your pushed branch and tell the agent where to pick up — for example, "Continue the work on this branch. Read the last commits and the open PR first."

Move your routines

Rebuild each Conductor routine as an Orca automation, created on your Remote Orca Server so it runs on schedule while your laptop is off.
