Privacy & Telemetry

What Orca product telemetry contains, how to opt out, and how it differs from hosted features.

This page describes optional product-usage telemetry in packaged Orca desktop builds. Accounts, mobile connections, notifications and other online features have separate data flows, described below and in our Privacy Policy.

Summary

  • Pseudonymous identifiers. Product telemetry uses random installation and session identifiers. Some usage summaries use a pseudonymous conversation identifier. These identifiers can link events from the same installation, session or conversation, so they are pseudonymous rather than anonymous. Accounts and other hosted features keep their own records.
  • Content boundaries. Product telemetry is designed to exclude file contents, prompts, agent responses, terminal output and free-form local paths. This does not describe content you send through an enabled hosted feature or to an AI provider you configure.
  • Opt-out controls. DO_NOT_TRACK=1 or ORCA_TELEMETRY_DISABLED=1 disables product telemetry for supported launches. You can also turn it off in Settings → Privacy.

What product telemetry contains

Events include the Orca version, operating system (for example, darwin, win32 or linux), CPU architecture, coarse OS release, release channel (stable or rc), and random installation and session identifiers. The telemetry event schema restricts accepted fields and bounds their values.

The categories include:

  • Lifecycle and feature use — app launches, onboarding (including system and selected interface language), feature interactions, and how repositories or workspaces are added or created. These events describe the action rather than the repository name, URL, path or contents. Actions from a paired mobile app that reach your desktop host, such as sending a chat message, can be recorded in that host's product telemetry.
  • Agents — agent kind, launch surface, bounded activity and usage summaries, and coarse error categories. Token-usage summaries include provider, input/output/cache token counts, a pseudonymous conversation identifier and a revision number; they do not include the conversation text.
  • Public plugin use — identifiers and versions of plugins installed from the official or community catalogs, with installation/update and trigger information. Private catalogs, local folders and development plugins are excluded from this event.
  • Settings and privacy controls — changes to an allowlisted set of preferences and telemetry consent choices. Free-form setting values are not part of these events.

The desktop PostHog transport does not add your account name or email to these events and disables SDK GeoIP enrichment. PostHog and network providers still receive request information, such as the source IP address, when events are sent. A random event identifier does not remove that request-level processing.

What is separate from product telemetry

  • Accounts and sign-ins process identity, organization, authentication and security records when you use those features. These records are separate from product-usage events.
  • Mobile and Relay process pairing, device, host, routing and connection metadata. Paired-runtime payload encryption does not conceal all service metadata.
  • Push notifications process device tokens and delivery information and can include notification titles, bodies and identifiers. Apple Push Notification service or Firebase Cloud Messaging receives information needed for delivery. Your device's notification-preview settings change what is shown on the device, not what those services receive.
  • Sharing, plugins and connectors process the uploaded content, package files, integration credentials, messages or events needed for the features you enable. Publicly shared content can be accessible to anyone with its public link.
  • Cloud Sandboxes process the hosted workspace, files, credentials and agent activity you choose to run there.
  • Support and diagnostics process material you submit, which can contain project or personal information. Review diagnostic bundles, screenshots and other attachments before sharing them.
  • Customer-selected AI providers and agents receive the context needed for your requested inference under their own terms and your configuration. We do not use customer code or prompts to train our own models; Orca telemetry settings do not change another provider's training or retention settings.

Turning off optional product telemetry does not turn off processing needed for separately enabled features, erase historical records or disable your configured AI providers. Website analytics also has a separate scope; see the Privacy Policy.

How to opt out

Any one of these controls is sufficient to disable product telemetry for the applicable desktop launch. Common CI environment markers, such as CI, also disable it:

  1. In the app. Settings → Privacy → turn "Share anonymous usage data" off. The stored preference persists across launches. Turning it off in the app can send one final event recording the opt-out before transmission stops.
  1. DO_NOT_TRACK=1 — disables product telemetry for that launch. Removing it restores your stored preference on the next launch.
  2. ORCA_TELEMETRY_DISABLED=1 — has the same override behavior as DO_NOT_TRACK.

Where product telemetry goes

  • Provider: PostHog Cloud's United States ingestion endpoint.
  • Retention and deletion: the PostHog project settings and applicable service arrangements determine retention; this page does not state a maximum retention period. Disabling telemetry does not erase events already sent.
