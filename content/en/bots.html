Bots quickstart

Create a bot, give it a job, put it on a schedule, and decide who can ask it.

A bot takes jobs from its chat, Slack, Linear, GitHub or a schedule. It works on your computer with your own Claude Code or Codex, or another supported agent, and reports back where you asked. When it needs a decision, it waits for you in Orca.

This page gets you from no bot to one with a first job, a schedule and a way for teammates to reach it. For ideas, see Use cases.

Each bot has a name, a purpose, a memory and automations, and lives in a folder on one computer.

Before you start

  • Orca on your computer, on the latest version.
  • Claude Code, Codex or another supported agent, installed and signed in on that computer. The bot runs on it, so its work counts against that plan.
  • To reach the bot from Slack, GitHub or Linear: sign in to Orca. Chat, schedules and Google work without it.

Create a bot

  1. In the sidebar's Bots section, select + (New bot or group), then New bot → Start from scratch. To start from one of the 24 templates instead, pick Browse templates.
  2. Give it a name and a picture.
  3. In the box that says Who it is and what it does, describe its job in a sentence. This is optional; you can also tell it in its first chat.
  4. Check the line that says where it runs: which computer and which agent. Select Change to pick another. A bot stays on the computer you pick.
  5. Select Create. Nothing is created until you do.
Don't see Bots?

Bots are on by default. If the sidebar has no Bots section, turn on Settings → Bots → Enable bots. Turning bots off hides them and stops new messages and automation runs. Their folders, memory and chats stay where they are.

Give it a first job

A bot you start from scratch greets you and asks what to work on first. Answer with one real task, for example:

  • "Every morning, summarize what changed in acme/web and what needs my review."
  • "When CI fails on a pull request, tell me if it's flaky or real."

The bot looks at what that task needs, does one small piece of it right away and shows you the result. Then it writes down what it's for, so every later chat starts from the same place. It keeps what it learns in its memory, so you can start a new chat for each job without repeating yourself.

For code changes, the bot hands the work to a worker: a Claude Code or Codex session in its own new workspace (a git worktree), so its changes stay out of your checkout. Workers show up under the bot in the sidebar, and their pull requests come back to the bot.

A template comes with a purpose and, for some, abilities and schedules. Its schedules start turned off. Its automations and connectors are set up in the bot's first chat, once you pick the repo or channel.

Talk to it

Select the bot in the sidebar to open its chat and ask it anything. In any Orca chat, type @ to mention a bot and bring it into the conversation.

When the bot needs you, for a decision, a sign-in or an approval, it says so, and the request waits under Needs you on the bot's Home until you answer. Pick one of the replies it suggests, or answer in your own words.

Put it on a schedule

Ask the bot in chat to do something on a schedule ("every weekday at 9") or when something happens ("when a pull request is opened in acme/web"). It sets up the automation and tells you where it runs and where the results go. The automation shows in the bot's panel, where you can pause or resume it.

Schedules can be hourly, daily, weekdays, weekly, cron or RRULE. The events a bot can start on depend on the connectors you've added. See Connectors and Scheduled automations.

The computer has to be on

A bot works while the computer it lives on is awake and online. The Keep computer awake setting in Orca prevents idle sleep while agents work; on a Mac, closing the lid still sleeps it. Requests from Slack, GitHub and Linear wait up to a day for the computer to come back. To keep a bot reachable, run it on a server you've paired with Orca and keep that server awake.

Step in

A bot's work stays in Orca, so you can pick it up at any point:

  • A worker's workspace: select the worker under the bot in the sidebar. You get its worktree with the editor, terminal and browser, where the worker left off.
  • A conversation from Slack, GitHub or Linear: it has its own chat under the bot. In Slack, look for the Open this thread in Orca link in the thread. In Linear, open the bot's agent session on the issue and select Open in Orca.
  • Its pull requests: review them like any other. They come from a worker's branch, not from your checkout.

Reach it from Slack, GitHub and Linear

Add a connector from the bot's Connectors tab. Then people ask it where they already work:

  • Slack: @scout in a channel, or a direct message. Each bot is its own Slack app.
  • GitHub: a mention on an issue or pull request, as the bot's How to ask line shows.
  • Linear: @Orca scout on an issue (Linear mentions go through the Orca app), or the label bot:scout.

Slack needs a one-time App Configuration Token per workspace. Your workspace may also need an admin to approve the bot's app. Connectors walks through it.

Decide who can ask

By default, only you can ask your bot. To let teammates ask it from Slack, Linear or GitHub, add them under Who can ask. Their requests run on your access, on your computer, so add only people you'd trust at your keyboard. When someone who isn't on the list asks, Orca normally replies with a note to ask you: privately on Slack, publicly on GitHub and Linear. You decide in Orca.

Before you add anyone, read Security. Consider switching the bot to Ask for approval, if its agent supports it; see Permissions.

What runs without you asking

Besides your asks and automations, a bot does two small jobs on its own. Both use your agent's plan:

  • Look around: a few times a day, a bot on Claude Code or Codex reads what's waiting for you in Slack, Linear, GitHub and your projects, and lists next steps under Suggestions. It is read-only: it can't post or change files. By default it is scheduled every 4 hours from 8 AM to 8 PM on weekdays, and runs while Orca is running on the bot's computer. Change how often, or turn it off, under Look around in the bot's settings.
  • Memory upkeep: by default, after a day with new chats, a bot on Claude Code or Codex tidies its memory that night after 3 AM, when it isn't paused or busy. A run missed while the computer was asleep can catch up once it wakes. You can review the changes, and restore MEMORY.md with Undo when it's available. Switch it to once a week, or turn it off, under Memory upkeep in the bot's settings.

Bring over a bot you already have

If you run a bot in another bot app, select + in the Bots section, then New bot → Import from another app…. Your new bot reads the old one, shows you a plan and sets itself up. Import skips key and login files, and you reconnect each service in Orca. See Import a bot.
