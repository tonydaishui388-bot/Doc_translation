Bot use cases

Eight jobs you can hand a bot today: where you ask, what it does, what comes back and where you step in.

Each walk-through below is a job a bot can do today, built on a template or a connector Orca ships. Every one follows the same shape: you ask (in Slack, Linear, GitHub, its chat or on a schedule), the bot works on your computer, it reports where you asked, and it waits for you where a person should decide.

The examples use a demo bot called Scout, a demo repo acme/web and a Slack channel #eng. Swap in your own.

Jump to a job:

  • Fix a bug someone reports in Slack
  • Triage new Linear issues
  • Watch CI and fix a failing check
  • A weekday standup on a schedule
  • Review a pull request when you're asked

Before you start

  • A bot set up as in the Bots quickstart. Start one from a template with + → New bot → Browse templates, or start from scratch and describe the job in its first chat.
  • The connectors each job names, added from the bot's Connectors tab. See Connectors.
  • A template's schedules start turned off. Turn them on from the bot's panel once you've told it which repo or channel to use.

Fix a bug someone reports in Slack

Start from: the Bug investigation template, with GitHub connected, plus Slack so people can ask there.

  • The ask. In #eng, Maya writes: "@scout checkout breaks on Safari, can you look?"
  • What the bot does. It starts a worker in a new git worktree that reproduces the bug and writes down the steps, then finds where it starts. It asks before it writes a fix. Once you agree, a worker fixes it, runs the tests and opens a pull request with your git login.
  • What comes back. A reply in the Slack thread: the cause, the test result and the pull request.
  • Where you step in. The "Start a fix?" question waits under Needs you. When the pull request is up, review it as you would any other. To look closer, open the worker from under the bot in Orca's sidebar: you land in its worktree with the editor, terminal and browser.

In Slack, look for the Open this thread in Orca link in the thread. It opens the same conversation in Orca.

Triage new Linear issues

Start from: a bot with Linear connected. There's no template for this one; describe it in chat.

  • The ask. In the bot's chat: "When a new issue is filed for the ENG team in Linear, check it has steps to reproduce, look for duplicates, and suggest a label and an owner. Ask me before you close anything."
  • What the bot does. It sets up an automation that starts on Linear's new-issue event. For each new issue it reads the description, searches for likely duplicates, and makes the changes you said it may make, as you.
  • What comes back. A short line per issue in the bot's chat: what it found and what it changed.
  • Where you step in. Anything you said it should ask about, such as closing a duplicate, waits under Needs you. People can also hand it a single issue. In Linear the mention goes through the Orca app, so they write @Orca scout (not @scout) on the issue, or add the label bot:scout.

Watch CI and fix a failing check

Start from: the CI failures template, with GitHub connected.

  • The ask. Set up by the template: "When a check fails, say whether it's flaky or real." Add to it in chat: "If it's real, ask me before you start a fix."
  • What the bot does. When a check fails in a repo you picked, it reads the failure, explains it, and says whether it looks flaky or real. It keeps a list of flaky checks and posts it Mondays at 9 AM.
  • What comes back. The explanation in the bot's chat.
  • Where you step in. For a real failure, it asks under Needs you whether to start a fix worker. Say yes, and the fix comes back as a pull request for you to review.

A weekday standup on a schedule

Start from: the Daily standup notes template, with GitHub and Linear connected, plus Slack if you want it posted there.

  • The ask. Set up by the template: weekdays at 9 AM. Turn the schedule on in the bot's panel. To share it, add in chat: "Also post it in #standup."
  • What the bot does. It looks at your workspaces, pull requests and issues, and writes what you and your agents did yesterday and what's next.
  • What comes back. The notes in the bot's chat, and in #standup as the bot's own Slack app if you asked.
  • Where you step in. Correct anything it got wrong in chat. It keeps what it learns in its memory, so the next day's notes start from there.

A schedule runs only while the bot's computer is awake. See Put it on a schedule.

Review a pull request when you're asked

Start from: the Pull request review template, with GitHub connected.

  • The ask. Set up by the template: when someone requests your review on a pull request in the repos you pick.
  • What the bot does. It reviews the pull request and lists risky changes and missing tests, with file and line.
  • What comes back. The findings in the bot's chat, for example: "#4121: the retry counter is never reset, so a second outage stops retries."
  • Where you step in. It doesn't comment on GitHub until you say it can. Tell it which findings to post, and it posts them as you. Its rules say approve, request changes or merge only when you ask; see what Orca enforces.

Draft release notes

Start from: the Release notes template, with GitHub connected.

  • The ask. In the bot's chat: "Draft the notes for 4.12." With Slack connected, you can ask in a channel instead: "@scout draft the notes for 4.12."
  • What the bot does. It reads the pull requests merged since the last release and writes notes for users in three groups: new, fixed and changed.
  • What comes back. The draft, in the thread or chat where you asked.
  • Where you step in. Edit the wording in chat. When it reads right, ask it to open a pull request that adds the notes to your changelog, or copy them where you publish.

Keep docs in sync with the code

Start from: the Docs upkeep template, with GitHub connected.

  • The ask. Set up by the template: Wednesdays at 10 AM, for the repos you pick.
  • What the bot does. It checks recently merged pull requests against your docs and lists the pages that no longer match, with the line that is now wrong.
  • What comes back. The list in the bot's chat.
  • Where you step in. Pick the pages to fix. A worker updates them in its own worktree and opens a pull request for you to review.

Respond to a webhook

Start from: the Deploy watch template, with GitHub connected so it can read the pull requests each deploy shipped. Any tool that can send a web request can start a bot the same way.

  • The ask. In the bot's chat: "Set up a webhook for our deploys." Copy the address with Copy URL on the automation's card and paste it into your deploy tool. Add a signing secret if the tool supports one.
  • What the bot does. Each time the tool calls, it summarizes the deploy from the pull requests it shipped and flags a deploy that failed. Orca hands it what the call carries as information, not as instructions.
  • What comes back. A summary in the bot's chat after each deploy.
  • Where you step in. Ask about anything that looks wrong. If the URL leaks, use Rotate key… on the webhook. See Webhooks.
It reports first, then acts

Most templates report what they found and ask before they change anything. You can widen what a bot does on its own in chat. Its asks wait under Needs you until you answer. To see what Orca enforces and what a bot is only told, read Security.

Write your own

A good first ask names four things:

  1. When: a schedule ("every weekday at 9"), an event ("when a check fails in acme/web") or just "now".
  2. What to do: one job, in a sentence.
  3. Where to report: the bot's chat, a Slack channel, or the issue or pull request it was asked on.
  4. What needs you: what it should ask about before it acts.

For example: "When a pull request is opened in acme/web, check it has a test for each fix. Tell me in #eng which ones don't. Don't comment on GitHub."
