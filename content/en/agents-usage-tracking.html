Usage & rate-limit tracking

Orca tracks usage for Claude Code, Codex, Muse Code, Gemini, Antigravity, OpenCode, Kimi Code, MiniMax, Cursor, ZCode, and GLM Coding Plans and surfaces it in the status bar, so you know how close you are to a rate limit before an agent stalls.

What's shown

  • Current usage against the active account's plan.
  • Time to reset for 5-hour, daily, weekly, and Claude Fable weekly windows (where applicable).
  • A warning chip when you cross 80% of a limit.
  • Provider credit balances when the provider reports one — Claude usage credits, OpenCode Zen balance, and Codex credits — alongside the usage limits. A provider that returns no balance reads as unavailable rather than zero.

How it works

The source depends on the provider. Orca reads local agent state where available, including Muse Code's local session logs; Muse usage is local token accounting and does not include a price estimate. OpenCode Go usage comes from its console API and needs your full opencode.ai Cookie header, including __Host-console_session, under Settings → Accounts. An auth cookie alone can find workspaces but cannot fetch Go usage. Other providers can require their own account setup in Settings.

For Cursor, Orca reads the existing Cursor sign-in on your computer and shows the plan's monthly usage in the status bar, Usage popover, and Settings → Accounts → Cursor. It does not sign you in; if the saved session expires, run cursor-agent login. A refused usage request reads as a usage failure, not an expired login.

For Antigravity, Orca reads the quota from Antigravity's own CLI — including its model-group pools — so you do not need a signed-in Gemini CLI, and checking does not spend quota. For ZCode, the Coding Plan quota appears alongside the session history it reads from on-disk transcripts.

You can also link a GLM Coding Plan directly under Settings → Accounts → GLM Coding Plan: pick the plan site (Z.AI or Zhipu BigModel) and save the plan API key. No ZCode CLI sign-in is required, and a saved key takes priority over the ZCode CLI sign-in. The plan appears in the usage roster like any other provider.

Multi-account accounting

The status bar always reflects the active account. Other configured accounts are visible in the account switcher with their own usage.

Usage roster

Click the usage segment in the status bar to open the Usage popover. It lists every tracked provider (icon · name · plan · soonest reset · per-window bars), sorted so the tightest limit is first. Use the header refresh control to re-read local usage state.

In a narrow window, the status bar keeps one line by hiding mini bars and labels, then showing one percentage per provider. If space is still tight, some provider chips become a +N chip. Click it to see every provider in the Usage popover. Providers at 80% usage or higher are collapsed last. When a provider reports a balance, it shows next to that provider's limits; in the narrow Compact segment, a provider that has hit a plan cap reveals its spendable balance.

  • Detailed — full bars, labels, and percentages for every window
  • Compact — only the tightest window per provider

Under Settings → Appearance, choose % used vs % remaining for how those numbers read.

Rows without live numbers show a short status instead: Loading usage…, not signed in, Usage unavailable, No usage data, or a provider-specific error. Claude and Codex rows can drill into account switching; Manage accounts opens Settings.

Mobile

On the companion app, open the host Accounts screen for the same switcher/usage readout. When Codex has earned rate-limit reset credits, spend one from that screen (see Mobile companion).

Estimated cost (Stats)

The Stats breakdown may show estimated cost for known model families, including Claude Opus 5.5, Fable 5.1, and Codex GPT-5.6 and GPT-6 Astra, Sol, and Luna. Orca uses a local price table, not a live bill from the provider. • inferred pricing marks an estimate where Orca inferred the model. A Codex cost marked • excludes unpriced models leaves those models out of the estimate; the Overview also flags a partial total. Prefer the provider console for authoritative spend.
